# 🚗 CarRental: Система управления прокатом автомобилей

Проект реализует полный цикл управления прокатом автомобилей с использованием современных технологий .NET, микросервисной архитектуры и событийного взаимодействия через Kafka.

## 📋 Обзор проекта

### **Архитектурные слои**
| Слой | Проект | Назначение |
|------|--------|------------|
| **API слой** | `CarRental.Api` | Веб-API с контроллерами и Kafka Consumer |
| **Доменный слой** | `CarRental.Domain` | Сущности, интерфейсы, тестовые данные |
| **Слой контрактов** | `CarRental.Application.Contracts` | DTO, маппинг (AutoMapper) |
| **Инфраструктурный слой** | `CarRental.Infrastructure` | EF Core, репозитории, миграции |
| **Сервис Kafka** | `CarRental.Kafka` | Генератор заявок и Kafka Producer |
| **Оркестратор** | `CarRental.AppHost` | Конфигурация и запуск контейнеров |
| **Тесты** | `CarRental.Tests` | Юнит-тесты бизнес-логики |
| **Общие настройки** | `CarRental.ServiceDefaults` | Конфигурация мониторинга и resilience |

## 🏢 Описание предметной области

Реализована объектная модель для системы проката автомобилей, включающая четыре основные сущности:

### **Основные сущности**
1. **Car (Автомобиль)** — 15 автомобилей различных марок, моделей и классов
2. **CarModel (Модель автомобиля)** — классификация по типу привода, кузову и классу
3. **ModelGeneration (Поколение модели)** — технические характеристики и цена аренды
4. **Client (Клиент)** — 15 клиентов с данными водительских прав
5. **Rental (Аренда)** — 19 записей об аренде автомобилей

## ✅ Выполненные задачи

### **1. Модель данных**
Автомобили классифицируются с использованием строковых типов:
- **DriveType** — тип привода (FWD, RWD, AWD, 4WD)
- **BodyType** — тип кузова (Sedan, SUV, Coupe, Hatchback, Van)
- **Class** — класс автомобиля (Economy, Premium, Luxury, Sports, Commercial)
- **Transmission** — тип трансмиссии (MT, AT, CVT)

### **2. Тестовые данные**
Подготовлен класс `TestData` с тестовыми данными:
- **15 моделей автомобилей** (от Lada Vesta до Porsche 911)
- **15 клиентов** с полными данными
- **15 поколений моделей** с техническими характеристиками
- **15 автомобилей** с государственными номерами
- **19 записей об аренде** с разными периодами

### **3. Unit-тесты**
Реализованы тесты с использованием xUnit для проверки аналитических запросов:
- `GetClientsByModelSortedByName()` — клиенты, арендовавшие автомобили указанной модели
- `GetCurrentlyRentedCars()` — автомобили, находящиеся в аренде на указанную дату
- `GetTop5MostRentedCars()` — топ-5 самых арендуемых автомобилей
- `GetRentalCountPerCar()` — количество аренд для каждого автомобиля
- `GetTop5ClientsByRentalAmount()` — топ-5 клиентов по суммарной стоимости аренд

### **4. Инфраструктура**
Реализованы классы для работы с данными:
- `AppDbContext` — контекст EF Core для MySQL
- `DbRepository` — реализация интерфейса `IRepository`
- Миграции Entity Framework Core

### **5. Контракты**
DTO-модели для операций создания/редактирования/чтения:
- `CarEditDto` / `CarGetDto`
- `ClientEditDto` / `ClientGetDto`
- `CarModelEditDto` / `CarModelGetDto`
- `ModelGenerationEditDto` / `ModelGenerationGetDto`
- `RentalEditDto` / `RentalGetDto`
- `MappingProfile` — конфигурация AutoMapper

### **6. API**
Реализованы контроллеры с полным CRUD и аналитикой:
- `CarsController` — управление автомобилями
- `ClientsController` — управление клиентами
- `CarModelsController` — управление моделями
- `ModelGenerationsController` — управление поколениями моделей
- `RentalsController` — управление арендами
- `AnalyticsController` — аналитические запросы

### **7. Kafka**
Инфраструктура worker-сервисов:
- `ContractGenerator` — генерирует случайные договоры аренды
- `KafkaProducerWorker` — публикует сообщения в Kafka топик
- `KafkaConsumerWorker` — читает сообщения из Kafka, сохраняет в БД (расположен в API)
- Конфигурация через `KafkaOptions` и `appsettings.json`

### **8. AppHost**
Конфигурация и запуск приложения с использованием Aspire:
- Контейнер MySQL для базы данных
- Контейнер Kafka для обмена сообщениями
- Оркестрация зависимостей между сервисами
- Поддержка Dashboard для мониторинга

### **9. Сервисные настройки**
Общая конфигурация для всех сервисов:
- Health checks
- OpenTelemetry для трассировки
- Service discovery
- Resilience patterns (HTTP resilience)
